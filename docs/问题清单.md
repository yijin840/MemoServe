### P0-02 · 上下文爆炸（大 chunk 导致 token 超标）

**现象**：如果某个文档章节很长（比如 200 行参数表），按当前切块逻辑会产生一个超大的 chunk。10 个这样的 chunk 全部传给 AI，上下文会远超 token 限制（通常 4096 或 8192），导致：
- AI 回答被截断
- 或直接报错（context length exceeded）

**根因**：`doc_loader.py` 的 `split_markdown()` 按标题切块，但没有控制每个 chunk 的长度。长章节（如参数表）会产生超大 chunk。

**修复方案**：

修改 `doc_loader.py`，在 `split_markdown()` 里增加 chunk 长度控制：

```python
# 第87行：修改 split_markdown() 函数签名，增加 max_chars 参数
def split_markdown(text: str, source_name: str, source_url: str = "", max_chars: int = 1200) -> list[dict]:
    """
    按 Markdown 标题切块，每块不超过 max_chars 字符。
    超过时按段落（\n\n）二次切分。
    """
    # ... 原有逻辑不变，在 flush() 里增加长度检查 ...

    def flush(path: list[str], body_lines: list[str]):
        nonlocal chunk_idx
        body = _clean("\n".join(body_lines))
        if len(body.strip()) < 30:
            return

        # ★ 新增：超长 chunk 按段落切分
        if len(body) > max_chars:
            paras = re.split(r'\n\n+', body)
            current_seg = []
            current_len = 0
            for p in paras:
                if current_len + len(p) > max_chars and current_seg:
                    seg_body = _clean("\n\n".join(current_seg))
                    if len(seg_body.strip()) > 30:
                        title_path = " > ".join(p for p in path if p)
                        cid = f"{source_name.replace(' ', '_')}_{chunk_idx:04d}"
                        chunks.append({
                            "id": cid,
                            "title_path": title_path,
                            "content": seg_body,
                            "source": source_name,
                            "url": source_url,
                        })
                        chunk_idx += 1
                    current_seg = [p]
                    current_len = len(p)
                else:
                    current_seg.append(p)
                    current_len += len(p)
            # 处理最后一段
            if current_seg:
                seg_body = _clean("\n\n".join(current_seg))
                if len(seg_body.strip()) > 30:
                    title_path = " > ".join(p for p in path if p)
                    cid = f"{source_name.replace(' ', '_')}_{chunk_idx:04d}"
                    chunks.append({
                        "id": cid,
                        "title_path": title_path,
                        "content": seg_body,
                        "source": source_name,
                        "url": source_url,
                    })
                    chunk_idx += 1
            return  # 超长 chunk 处理完直接返回，不走下面的单次追加

        # 原有逻辑：正常大小的 chunk 直接追加
        title_path = " > ".join(p for p in path if p)
        if not title_path:
            title_path = source_name
        cid = f"{source_name.replace(' ', '_')}_{chunk_idx:04d}"
        chunks.append({
            "id": cid,
            "title_path": title_path,
            "content": body,
            "source": source_name,
            "url": source_url,
        })
        chunk_idx += 1
```

**参数说明**：
- `max_chars = 1200`：每个 chunk 最多 1200 字符（约 400-600 tokens，留足余量）
- 按 `\n\n` 切分，保持段落完整性
- 超长 chunk 切成多个子 chunk，共享同一个 `title_path`

**改动文件**：`doc_loader.py`，约 50 行改动（修改 `flush()` 函数）

**验证方法**：
1. 重启 server.py，观察启动日志里的 chunk 数量（应该比之前多，因为大块被细分了）
2. 问一个会命中长参数表的问题（如"KYC 需要哪些参数"）
3. 观察回答是否完整（没有被截断）

### P1-01 · 时间戳单位矛盾（毫秒 vs 秒）

**现象**（多轮测试轮5）：
```
轮3 问 401排查 → AI 答：时间戳用毫秒
轮5 问 时间戳是秒还是毫秒 → AI 答：时间戳以秒为单位
```
AI 前后矛盾。

**根因**：知识库中两处文档用了不同单位：
- HMAC 签名认证 `request_timestamp` → **毫秒**
- 查询接口 `former_time` / `latter_time` → **秒**

AI 检索到哪块就按哪块答，不区分场景。

**修复方案**：

修改 `src/agents/kb_agent.py` 的 `chat()` 方法，检测"时间戳"相关问题，强制同时检索两类文档：

```python
# 第153-155行：修改检索逻辑
# ★ 新增：时间戳相关问题强制增强检索
doc_result = search_docs(question)

# 如果问题含"时间戳"，强制同时搜"HMAC"和"查询接口"
if "时间戳" in question or "timestamp" in question.lower():
    result_hmac = search_docs("HMAC 签名 时间戳 毫秒")
    result_query = search_docs("查询接口 时间戳 秒 former_time latter_time")
    # 合并结果，去重
    seen = {c["id"] for c in doc_result.get("chunks_used", [])}
    for c in result_hmac.get("chunks_used", []) + result_query.get("chunks_used", []):
        if c["id"] not in seen:
            doc_result["chunks_used"].append(c)
            seen.add(c["id"])
```

同时修改 `rag_store.py` 的 `search()` 函数，确保"毫秒"和"秒"都能被正确检索到（不强依赖此修改，主要靠上面的增强检索）。

### P1-02 · mem0 语义记忆不工作

**现象**：
- 跨会话记忆完全失效
- 所有异常被 `try/except` 吞掉，不报错只返回空结果
- `mem0_manager.py` 配置了本地 embedding，但初始化可能失败

**根因**：
1. `mem0_manager.py` 的 `get_memory()` 初始化可能失败（Qdrant 路径权限问题、依赖缺失等）
2. 初始化失败后 `_instance` 为 `None`，后续所有调用都直接返回空
3. 没有可视的错误提示，难以排查

**修复方案**：

修改 `mem0_manager.py`，增加详细的错误日志和初始化状态检查：

```python
# 第16-38行：重写 get_memory()
def get_memory() -> Memory:
    """获取 mem0 实例（单例）"""
    global _instance
    if _instance is not None:
        return _instance

    config = {
        "vector_store": {
            "provider": "qdrant",
            "config": {"path": str(MEM0_DB)}
        },
        "embedder": {
            "provider": "huggingface",
            "config": {"model": "paraphrase-multilingual-MiniLM-L12-v2"}
        },
    }
    try:
        _instance = Memory.from_config(config)
        print(f"[mem0] ✅ 初始化成功（存储：{MEM0_DB}，embedding：本地）")
        return _instance
    except Exception as e:
        print(f"[mem0] ❌ 初始化失败: {e}")
        print(f"[mem0] 请检查：1) {MEM0_DB} 目录权限  2) 是否安装 sentence-transformers")
        _instance = None
        return None


def remember(user_id: str, question: str, answer: str, confidence: float):
    """存储一次问答到记忆"""
    if confidence < 0.5:
        return
    try:
        m = get_memory()
        if m is None:
            print(f"[mem0] ⚠️ 跳过存储（mem0 未初始化）")
            return
        m.add(
            messages=[
                {"role": "user", "content": question},
                {"role": "assistant", "content": answer}
            ],
            user_id=user_id,
            metadata={"confidence": confidence}
        )
        print(f"[mem0] ✅ 已存储记忆（user_id={user_id}）")
    except Exception as e:
        print(f"[mem0] ❌ 存储失败: {e}")


def recall(query: str, user_id: str = "default", top_k: int = 3) -> list[str]:
    """语义搜索历史记忆"""
    try:
        m = get_memory()
        if m is None:
            print(f"[mem0] ⚠️ 跳过搜索（mem0 未初始化）")
            return []
        results = m.search(query, user_id=user_id, limit=top_k)
        memories = [r.get("memory", "") for r in results if r.get("memory")]
        if memories:
            print(f"[mem0] ✅ 召回 {len(memories)} 条记忆")
        return memories
    except Exception as e:
        print(f"[mem0] ❌ 搜索失败: {e}")
        return []
```

### P1-04 · 多主题匹配时未做反问确认

**现象**：用户问"KYC"，可能同时匹配到多个不同主题的 chunk（提交材料、查询状态、失败重试）。当前系统把所有 chunk 都传给 AI，AI 可能全部回答或混淆。

**期望行为**：检索到多个不同主题时，先列出选项让用户选择，而不是一股脑全答。

**修复方案**：

修改 `src/agents/kb_agent.py` 的 `chat()` 方法，在检索后增加"主题聚类 + 反问"逻辑：

```python
# 第163行开始：在检索后增加主题聚类
chunks = doc_result.get("chunks_used", [])

# ★ 新增：多主题检测
if len(chunks) >= 3:
    # 按 title_path 的第一级聚类（通常是 ## 标题）
    topics = {}
    for c in chunks:
        topic = c["title_path"].split(" > ")[0]  # 取第一级标题
        if topic not in topics:
            topics[topic] = []
        topics[topic].append(c)

    # 如果聚类数 >= 2，且每个主题都有高分段块，做反问
    if len(topics) >= 2 and all(topics[t].get("score", 0) >= 3.0 for t in topics):
        topic_list = list(topics.keys())
        options = "\n".join([f"{i+1}. {t}" for i, t in enumerate(topic_list)])
        clarify = f"您的问题涉及多个方面，请问您想了解哪个方面？\n{options}\n\n请告诉我序号或直接描述您的需求。"
        return {
            "answer": clarify,
            "source": "clarify",
            "doc_hits": len(chunks),
            "confidence": 1.0,
            "chunks_used": chunks[:3],  # 只返回前3个用于展示
            "method": "clarify",
            "topics": topic_list,  # 前端可以用这个做快速按钮
        }
```
