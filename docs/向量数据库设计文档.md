## 一、设计概述

### 1.1 为什么选择 ChromaDB

| 考量 | 说明 |
|------|------|
| **本地持久化** | 数据保存在 `./chroma_db/`，无需外部服务，部署简单 |
| **Python 原生** | 与项目技术栈完全兼容，无额外依赖服务 |
| **元数据过滤** | 支持 `where` 条件查询，天然支持 `category` 分类过滤 |
| **cosine 距离** | 默认 `cosine` 空间，与 sentence-transformers 输出直接匹配 |
| **降级友好** | 依赖缺失时自动降级到 TF-IDF，不中断服务 |

### 1.2 整体架构

```
┌─────────────────────────────────────────────────┐
│            doc_loader.py                       │
│  切分 Markdown → chunks（含 category 字段）    │
└─────────────────┬───────────────────────────┘
                  │ 调用 sync_chunks_to_vector()
┌─────────────────▼───────────────────────────┐
│          rag_store.py                         │
│  ChromaDB 语义检索 / TF-IDF 降级检索         │
│  - collection: doc_qa_chunks               │
│  - embedding: paraphrase-multilingual-MiniLM│
│  - 元数据: source/title_path/url/category  │
└─────────────────┬───────────────────────────┘
                  │ 返回 hits [{"chunk":..., "score":...}]
┌─────────────────▼───────────────────────────┐
│          agent.py                             │
│  分类推断 → search_docs(category=...)        │
│  → ChromaDB where 过滤 或 TF-IDF 预过滤    │
└─────────────────────────────────────────────┘
```

### 1.3 依赖与版本

| 依赖 | 版本 | 用途 |
|------|------|------|
| `chromadb` | 0.6.3 | 向量数据库引擎 |
| `sentence-transformers` | 5.1.2 | 文本向量化（embedding） |
| `paraphrase-multilingual-MiniLM-L12-v2` | — | 384 维多语言 embedding 模型（~470MB） |

> **模型选择理由**：知识库含中英文混排 API 文档，必须选多语言模型；`MiniLM-L12` 在精度和速度间取得良好平衡，384 维向量存储和检索效率较高。

## 二、数据模型设计

### 2.1 Collection 定义

| 属性 | 值 |
|------|-----|
| **collection 名称** | `doc_qa_chunks` |
| **距离函数** | `cosine`（相似度 = 1 - distance） |
| **持久化路径** | `./chroma_db/`（可通过 `CHROMA_PATH` 环境变量覆盖） |

### 2.2 字段设计

每个 chunk 在 ChromaDB 中以一条记录存储，结构如下：

| ChromaDB 字段 | 来源 | 说明 |
|---------------|------|------|
| `id` | `chunks.json` 中的 `id` 字段 | 格式：`{source_name}_{chunk_idx:004d}`，如 `Card_issuing_API_文档_0003` |
| `embedding` | sentence-transformers 实时计算 | 384 维浮点向量，由 `title_path + "\n" + content[:400]` 生成 |
| `document` | `title_path + "\n" + content[:400]` | 用于向量化的文本（截断到 400 字符） |
| `metadata.source` | `chunks.json` 中的 `source` | 文档来源名称，如 `Card issuing API 文档` |
| `metadata.title_path` | `chunks.json` 中的 `title_path` | 完整标题路径，如 `Card issuing API 文档 > KYC > 提交用户 KYC 数据` |
| `metadata.url` | `chunks.json` 中的 `url` | 文档来源 URL（可能为空） |
| `metadata.content` | `chunks.json` 中的 `content[:800]` | 完整内容前缀（存到元数据便于直接查看，不影响检索） |
| `metadata.category` | 从 `title_path` 一级路径提取 | 分类字段，如 `Card issuing API 文档`、`Native MM API Documentation` |

### 2.3 category 字段设计

**提取规则**：`title_path.split(" > ")[0]`

```
title_path 示例                            →  category
──────────────────────────────────────────────────────────
Card issuing API 文档 > KYC > 提交KYC数据  →  Card issuing API 文档
Native MM API Documentation > Deposit > ...   →  Native MM API Documentation
KYC — 搜索导入 > 来源3                    →  KYC — 搜索导入
```

**设计决策**：
- 不从文档内容推断分类，避免误分类
- 用 `title_path` 一级路径，与文档结构天然一致
- ChromaDB `where` 过滤是精确匹配，不匹配时返回空（不降级），避免跨分类污染

### 2.4 与 chunks.json 的对应关系

| chunks.json 字段 | ChromaDB 对应 | 备注 |
|-----------------|---------------|------|
| `id` | `id` | 完全一致 |
| `title_path` | `metadata.title_path` + `document`（前缀） | 双份存储，metadata 用于过滤，document 用于向量化 |
| `content` | `metadata.content`（截断到 800 字符） | ChromaDB 不存完整内容，完整内容从 `chunks.json` 读取 |
| `source` | `metadata.source` | 完全一致 |
| `url` | `metadata.url` | 完全一致 |
| `category` | `metadata.category` | v4.0.0 新增 |

> **重要**：ChromaDB 只存向量和元数据，不存完整 chunk 内容。检索时通过 `id` 到 `chunks.json` 取完整内容。这是有意设计——ChromaDB 负责"找最相关的 chunk ID"，`chunks.json` 负责"提供完整内容"。

## 三、实现细节

### 3.1 初始化流程（`rag_store.py` 第 25-43 行）

```python
CHROMA_PATH = Path(os.getenv("CHROMA_PATH", "./chroma_db"))

CHROMA_OK = False
_collection = None
_embedder = None

def _init_chroma():
    global CHROMA_OK, _collection, _embedder
    try:
        import chromadb
        from sentence_transformers import SentenceTransformer
        client = chromadb.PersistentClient(path=str(CHROMA_PATH))
        _collection = client.get_or_create_collection(
            name="doc_qa_chunks",
            metadata={"hnsw:space": "cosine"},
        )
        _embedder = SentenceTransformer(
            "paraphrase-multilingual-MiniLM-L12-v2"
        )
        CHROMA_OK = True
    except ImportError:
        print("⚠️ 向量检索依赖未安装，使用 TF-IDF 关键词降级")
    except Exception as e:
        print(f"⚠️ ChromaDB 初始化失败: {e}")

_init_chroma()  # 模块导入时自动执行
```

**关键点**：
- 模块导入时自动初始化，不阻塞服务启动
- 依赖缺失时 `CHROMA_OK = False`，自动降级 TF-IDF
- `PersistentClient` 持久化到磁盘，`get_or_create_collection` 保证幂等

### 3.2 向量同步（`sync_chunks_to_vector`，第 104-118 行）

```python
def sync_chunks_to_vector(chunks: list[dict]):
    """把所有文档块同步进 ChromaDB（服务启动时调用）"""
    if not CHROMA_OK or _collection is None:
        return
    batch_size = 64
    for i in range(0, len(chunks), batch_size):
        batch = chunks[i:i+batch_size]
        ids   = [c["id"] for c in batch]
        # 用 title_path + content 前缀做向量化（前 400 字符足够表达主题）
        texts = [c["title_path"] + "\n" + c["content"][:400] for c in batch]
        metas = [{
            "source": c["source"],
            "title_path": c["title_path"],
            "url": c.get("url", ""),
            "content": c["content"][:800],   # 存前缀便于直接查看
            "category": c.get("category", ""),
        } for c in batch]
        embeds = _embedder.encode(texts).tolist()
        _collection.upsert(
            ids=ids, embeddings=embeds,
            documents=texts, metadatas=metas,
        )
    print(f"[RAG] 同步 {len(chunks)} 个文档块到向量库")
```

**调用时机**：`server.py` 启动时（`startup_event` 或首次请求时懒加载）。

**upsert 语义**：已存在的 `id` 会覆盖更新，新增的 `id` 会插入，天然支持增量更新。

### 3.3 语义检索（`semantic_search`，第 121-157 行）

```python
def semantic_search(
    query: str,
    top_k: int = 5,
    threshold: float = 0.3,
    category: str = "",
) -> list[dict]:
    """语义检索，返回 [{"chunk": {...}, "score": float}, ...]"""
    if not CHROMA_OK or _collection is None or _collection.count() == 0:
        return []
    try:
        q_embed = _embedder.encode(query).tolist()
        n = min(top_k * 2, max(1, _collection.count()))
        # category 非空时加 where 过滤
        where_filter = {"category": category} if category else None
        res = _collection.query(
            query_embeddings=[q_embed],
            n_results=n,
            where=where_filter,
            include=["metadatas", "distances"],
        )
        hits = []
        for meta, dist in zip(res["metadatas"][0], res["distances"][0]):
            score = 1.0 - dist  # ChromaDB 返回 distance，转成相似度
            if score >= threshold:
                hits.append({
                    "chunk": {
                        "id": "",
                        "title_path": meta["title_path"],
                        "content": meta["content"],
                        "source": meta["source"],
                        "url": meta.get("url", ""),
                        "category": meta.get("category", ""),
                    },
                    "score": round(score, 3),
                })
        return hits[:top_k]
    except Exception as e:
        print(f"[RAG] 语义检索失败: {e}")
        return []
```

**threshold = 0.3 的含义**：相似度低于 0.3（即 cosine distance > 0.7）的结果被认为不相关，直接过滤。`1.0` = 完全相同，`0.0` = 完全不相关。

### 3.4 统一检索入口（`search_docs`，第 162-184 行）

```python
def search_docs(
    query: str,
    chunks: list[dict],
    top_k: int = 5,
    category: str = "",
) -> list[dict]:
    """
    优先 ChromaDB 语义检索，降级 TF-IDF 关键词。
    返回 [{"chunk": {...}, "score": float, "method": "semantic"|"keyword"}, ...]
    """
    # 优先走向量检索
    if CHROMA_OK:
        hits = semantic_search(query, top_k=top_k, threshold=0.3, category=category)
        if hits:
            return [dict(h, method="semantic") for h in hits]

    # TF-IDF 降级：先按 category 预过滤 chunks
    if category:
        filtered = [c for c in chunks if c.get("category", "") == category]
        if filtered:
            chunks = filtered
        else:
            return []  # category 不匹配时返回空，不降级到全量

    hits = keyword_search(query, chunks, top_k=top_k, threshold=0.05)
    return [dict(h, method="keyword") for h in hits]
```

**降级策略总结**：

| 阶段 | 条件 | 行为 |
|------|------|------|
| 1 | `CHROMA_OK=True` 且向量检索有结果 | 返回语义检索结果（`method="semantic"`） |
| 2 | `CHROMA_OK=True` 但向量检索无结果 | 继续走 TF-IDF 降级 |
| 3 | `CHROMA_OK=False` | 直接走 TF-IDF |
| 4（TF-IDF） | 指定了 `category` 且有匹配的 chunk | 只在匹配 category 的 chunks 中做 TF-IDF |
| 5（TF-IDF） | 指定了 `category` 但没有匹配的 chunk | 返回 `[]`，**不降级到全量**（避免跨分类污染） |

## 四、分类检索设计

### 4.1 分类推断逻辑（`agent.py`）

```python
_cat_kw = {
    "Card issuing API 文档": [
        "KYC", "开卡", "充值", "冻结", "解冻", "信用卡",
        "card", "issue", "freeze", "unfreeze", "recharge",
    ],
    "Native MM API Documentation": [
        "deposit", "exchange", "asset", "MM", "充值卡",
        "提现", "withdraw", "transfer",
    ],
}
```

推断流程：
1. 遍历 `_cat_kw`，检查 `question` 是否包含任意关键词
2. 匹配到则返回对应 category
3. 未匹配则返回 `""`（不过滤）

### 4.2 ChromaDB where 过滤

ChromaDB 的 `where` 参数是精确匹配：

```python
where_filter = {"category": "Card issuing API 文档"}
# 只返回 metadata.category == "Card issuing API 文档" 的记录
```

**限制**：ChromaDB `where` 不支持 `LIKE` 或正则表达式，分类名称必须精确匹配。

### 4.3 TF-IDF 预过滤

当 ChromaDB 不可用时，在 TF-IDF 检索前先做内存过滤：

```python
if category:
    filtered = [c for c in chunks if c.get("category", "") == category]
    if filtered:
        chunks = filtered
    else:
        return []  # 不匹配时返回空，不降级
```

### 4.4 分类检索效果示例

```
用户问题： "KYC 认证需要什么材料？"
  → 推断 category = "Card issuing API 文档"
  → ChromaDB where {"category": "Card issuing API 文档"}
  → 只在 133 个该分类 chunk 中检索（而非全量 154 个）
  → 结果更精准，跨分类污染为 0
```

### 6.3 性能优化建议

| 场景 | 建议 |
|------|------|
| 向量库 > 10000 个 chunk | 考虑按文档来源分多个 collection |
| 检索响应时间 > 2 秒 | 检查 `paraphrase-multilingual-MiniLM-L12-v2` 是否在用 CPU 推理（无 GPU 时正常） |
| 内存占用过高 | `PersistentClient` 会缓存索引，可考虑切换到 `HttpClient`（需要单独部署 ChromaDB server） |
| 磁盘空间不足 | `chroma_db/` 约占用 `chunk数 × 384 × 4 bytes × 1.5`（索引开销），154 个 chunk 约 10MB |

## 附录：ChromaDB 与 TF-IDF 对比

| 维度 | ChromaDB（向量检索） | TF-IDF（关键词检索） |
|------|----------------------|---------------------|
| **语义理解** | ✅ 能理解"充值"和"deposit"是同类 | ❌ 只能匹配字面 |
| **跨语言** | ✅ 多语言模型 | ❌ 中英文需分别分词 |
| **依赖** | `chromadb` + `sentence-transformers`（~500MB） | 零依赖（纯标准库） |
| **速度** | 较快（向量检索） | 快（内存计算） |
| **精度** | 高（语义相似度） | 中（关键词匹配） |
| **category 过滤** | ✅ `where` 原生支持 | ✅ 内存过滤（Python 列表推导） |
| **降级** | 失败时降级到 TF-IDF | 最终降级，无再降级 |
