## 3. 问题分析与建议

### 3.1 意图分类器盲区（2 条拒答根因）

两条拒答的共同特征：问题使用了**纯技术术语**（"USDT和USDC"、"幂等性"），意图分类器无法将其归入已知业务意图（开卡/充值/KYC/FAQ 等），直接返回 `unknown` 并拒答。

**知识库内容本身正确**，换成业务场景问法后立即通过：

| 原问题（拒答）| 替代问法（通过）|
|-------------|--------------|
| "USDT和USDC有什么区别？" | "充值时用USDT还是USDC，有什么区别？" |
| "什么是幂等性？为什么重要？" | "cust_tx_id重复提交会怎样？" |

**根本原因**：意图分类器的 prompt/分类规则中，未覆盖"加密货币比较"和"幂等性"等抽象技术问题。

**修复建议**：在 `knowledge_agent.py` 或意图分类器的 prompt 中，将以下 intent 补充进来：
- `crypto_topup`：关于稳定币、USDT、USDC、区块链充值的问题
- `technical_concept`：关于 API 抽象概念（幂等、时钟偏差等）的问题

---

### 3.2 Apple Pay 问题回答不够精确（G-16）

回答命中了"不支持"，但未明确指出"哪些卡支持 / 哪些不支持"，只是模糊带过。

**建议**：在 GLOSSARY.md 的 Apple Pay 条目中，增加一张对照表：

| 卡片类型 | 支持 Apple Pay |
|---------|--------------|
| Native 虚拟卡 | ✅ 支持 |
| UQ Option 2 | ✅ 支持 |
| UQ Option 1 | ❌ 不支持 |
| Native 实体卡 | ✅ 支持（NFC） |

---

### 3.3 KYC 问题命中不够全面（G-05）

GLOSSARY.md 补充了 KYC 的结构性描述，FAQ.md 中也有 KYC 审核时长等内容，两者可以联合检索，实际表现良好。但"无KYC"、"标准KYC" 这两个关键词在回答中没有出现（实际答案用的是 `No KYC`、`Standard KYC` 英文形式）。

**建议**：GLOSSARY.md 中 KYC 条目同时保留中英双语关键词，方便不同问法命中。
