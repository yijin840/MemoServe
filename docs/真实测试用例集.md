### TC-04 · 虚拟卡 vs 实体卡对比

**用户问题**：虚拟卡和实体卡有什么区别，哪个更适合线上支付？

**客服实际回答**：

> 你好！关于虚拟卡和实体卡的区别以及线上支付选择：
> 
> ## 区别
> | 特性 | 虚拟卡 | 实体卡 |
> |------|--------|--------|
> | 物理形态 | 无实体，仅数字信息 | 有实体卡片 |
> | 制卡周期 | 即时生成 | 需1–2周制卡 |
> | 激活方式 | API激活后获完整卡号 | 需提交cvv，部分需手持拍照 |
> | 适用场景 | 线上支付、即时使用 | 线下刷卡、ATM取现 |
> 
> ## 线上支付推荐
> **虚拟卡更合适**。激活后立刻获得完整卡号、cvv、有效期，可直接用于线上支付。

**测试要点**：

- ✅ 表格形式多维度对比
- ✅ 有明确使用建议

### TC-05 · 机构信息 + API 错误

**用户问题**：我的机构名称是TechPay Ltd，我们在对接API时遇到了401错误

**客服实际回答**：

> 你好！针对你提到的 401 错误，通常是身份权限认证失败。请按以下步骤排查：
> 
> **1. 确认 HMAC 签名流程**
> - 时间戳：毫秒级 UNIX 时间戳，需与服务器时间差 < 5 分钟
> - Authorization header 格式：`Railone:你的ApiKey:请求时间戳:签名`
> - 签名算法：HMAC_SHA256
> - Access-Passphrase：若创建 API Key 时设置了密码，必须添加该 header
> 
> **2. 检查 IP 白名单**

**测试要点**：

- ✅ 给出详细的 HMAC 401 排查步骤
- ✅ 说明签名格式和时间戳要求

### TC-06 · 后续对话带出记忆

**用户问题**：我们TechPay Ltd遇到的API 401问题，认证方式应该怎么配置？

**客服实际回答**：

> 你好！关于 TechPay Ltd 遇到的 API 401 问题，通常是由 HMAC 认证配置错误导致。以下是标准的认证配置步骤：
> 
> 1. 获取凭证：确保已在机构后台申请了 API Key 和 API Secret
> 2. 构造签名：UNIX 时间戳（毫秒）+ HTTP 方法 + API Key + 请求路径 + 请求 body
> 3. 生成签名：HMAC_SHA256 算法
> 4. 设置请求头：`Authorization: Railone:ApiKey:request timestamp:signature`

**测试要点**：

- ✅ 回答中出现了「TechPay Ltd」——上下文有传递
- ✅ 给出完整认证配置步骤
